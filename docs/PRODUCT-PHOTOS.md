# Product photography — how to swap the procedural renders for actual photos

The site ships with **procedural renders** generated by Pillow (see `scripts/gen-product-images.py`) — clean, well-lit, but unmistakably synthetic. They were created because AI image generation tools (`higgsfield`, `image_gen`) were not available in the build environment, and stock photo CDNs were blocked from the sandbox. **Replace them with real photography** as soon as possible — beauty ecommerce converts significantly higher with real product photos.

## 2. How to replace them

### Option A — drop your photo over the file (simplest)

1. Save your new photo as **exactly the same filename**, same folder: `public/products/beauty-case-rose-front.png`
2. Re-deploy: `vercel --prod` from your terminal
3. The site picks it up automatically (no code change needed)

### Option B — point the catalog at different filenames

If you prefer different names (e.g. you use `.webp` for performance), edit `src/lib/products.ts` and update the `images` array on each variant. Then drop the matching files in `public/products/`.

### Recommended photo specs

| Use | Format | Min size | Aspect | Notes |
| --- | --- | --- | --- | --- |
| Hero front (cards + product hero) | `.webp` or `.jpg` | 1600x2000 | 4:5 | Clean cream background, no shadows under product |
| Case open | `.webp` or `.jpg` | 1600x2000 | 4:5 | Mirror reflecting a soft light, gloss visible |
| Detail close-up | `.webp` or `.jpg` | 1200x1500 | 4:5 | Stitching / texture / hardware |
| Lifestyle | `.webp` or `.jpg` | 1600x2000 | 4:5 | In a handbag, on a vanity, in a hand |

### Performance tips

- Use `.webp` (or AVIF) — much smaller than `.png` for photos. CAELIA serves through `next/image` which auto-converts to WebP for modern browsers.
- Re-export at 2x DPR — Next will downscale on phones, but you keep crisp on retina.
- Keep each front photo under 500 KB.
- Use the **same filename** so the catalog doesn''t need to change.

### Color accuracy

The product variants in the catalog use these swatch hexes (visible as colored dots next to the variant label):

| Variant | Swatch hex | What it should look like |
| --- | --- | --- |
| Rose | `#d49b96` | warm dusty rose, like a faded terracotta |
| Noir | `#1f1d1c` | near-black, soft matte |
| Ivory | `#efe5d8` | warm off-white, slight yellow undertone |

Make sure your photography respects these — if the real case is brighter/darker than the swatch, customers will think they received the wrong color.

## 3. The 3D viewer

The **Studio 3D** section on the home page (`<Caelia3DExplorer />`) uses a Three.js model that lives in `src/lib/caelia/` and renders in `src/components/caelia-{model,viewer}.tsx`. It does **not** depend on the product photos — it is its own asset, built from primitive Three.js geometry. If you swap the physical product''s color or material, update `src/lib/caelia/variants.ts` and `src/lib/caelia/textures.ts` to match.

The 3D section is the **only** 3D component on the landing. The Beauty Finder quiz (`CaeliaFinder`) was intentionally removed from the home page so the 3D owns the interactive space without competition.
